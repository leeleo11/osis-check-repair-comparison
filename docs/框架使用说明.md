# 六框架使用说明

## 共享合同

Runner 把外部 seeded 工程复制到 ignored run 的 private 区和 candidate_project。Adapter 只收到净化任务、candidate 根、统一技能快照、模型与预算。候选工具拒绝绝对路径、父目录跳转和非文本文件。

## T1 Direct

T1 没有工具循环。Harness 在一次请求中加入公开任务、确定性的技能正文包与当前候选文本。回复中的 FILE 块经过同一 CandidateWorkspace 路径门禁后写入。任何第二次补问都会改变架构定义，因此禁止。

## T2 LangGraph

T2 使用 langchain.agents.create_agent 和 stream_mode=values。每条消息、工具名和有限预览写入 ignored trace。可用工具是技能索引/读取、候选列举/读取/写入和 Python 语法检查。

## T3 smolagents

T3 使用 CodeAgent。模型通过 CodeAct 调用同一组 Python 工具；additional_authorized_imports 为空，避免绕过候选目录边界。

## T4 OpenHands

T4 通过 load_skills_from_dir 和 AgentContext 装载 AgentSkills。提示词只要求先调用 InvokeSkillTool，再检查候选并做最小修复；不会把完整技能索引和参考文件清单重复塞入 prompt。OpenHands 事件只保存类型、工具名和响应 ID，便于确认原生技能是否被调用并控制日志体积。

## T5 CrewAI

T5 固定为 diagnoser、repairer、verifier 三角色顺序流程。诊断者和复核者使用只读 BoundedTools；只有修复者拿到 write_candidate_file。三者均关闭 delegation 与 code execution，避免框架默认能力绕过目录门禁。

## T6 OSIS-AI

T6 为每条 run 建立 t6_isolated_project，复制同一技能快照和候选 py，启动以该目录为 cwd 的 OpenCode 服务，并使用父仓库 opencode_client。完成后只把 py 同步回 candidate_project。Campaign 无论 jobs 设置为何值都串行执行 T6。
