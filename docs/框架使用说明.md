# 验算修复线实验使用说明

比较 T1–T6 能否定位并修复同一处验算失败。题面只有目标验算项。种错做法、原因码真值和 NG 清单不进模型输入。六个架构用同一份去掉 `templates/` 的技能快照和同一份候选工程。环境用 `uv`，不要提交 `.venv` 或 `.venvs`。

```powershell
$env:OSIS_PARENT_REPO = "C:\path\to\osis-skill-enhance-main"
$env:OSIS_MODEL_API_KEY = "<key>"
$env:OSIS_MODEL_BASE_URL = "http://<gateway>/v1"
uv sync --python 3.13 --extra test
uv run python scripts/setup_framework_envs.py
uv run python scripts/create_skill_snapshot.py --parent-repo $env:OSIS_PARENT_REPO
```

快照会丢掉所有名为 `templates` 的目录。模板是种错前的正确工程，留着就能对照出改动。正式运行时 runner 还会再过滤一次，写成该次 run 的 `public_skills`。

另备一个专用 OSIS scratch 工程，以及带 `pyosis` 的 Python。不要指向正在人工使用的工程。

## 怎么开跑

先不调模型，只核对题单：

```powershell
uv run python scripts/run_dataset.py `
  --parent-repo $env:OSIS_PARENT_REPO `
  --architecture T2 `
  --skills-dir tmp\check-repair-skill-snapshot `
  --dry-run
```

一条正式任务。`--architecture` 换成 T1–T6 中的一个：

```powershell
uv run python scripts/run_dataset.py `
  --parent-repo $env:OSIS_PARENT_REPO `
  --architecture T2 `
  --skills-dir tmp\check-repair-skill-snapshot `
  --osis-project C:\path\to\scratch-project `
  --osis-model-python C:\path\to\python.exe `
  --model $env:OSIS_MODEL `
  --label formal-v1 `
  --seed 0
```

六架构一起跑：

```powershell
uv run python scripts/run_campaign.py `
  --parent-repo $env:OSIS_PARENT_REPO `
  --architectures T1 T2 T3 T4 T5 T6 `
  --skills-dir tmp\check-repair-skill-snapshot `
  --osis-project C:\path\to\scratch-project `
  --osis-model-python C:\path\to\python.exe `
  --model $env:OSIS_MODEL `
  --label formal-v1 `
  --seed 0 `
  --jobs 2 `
  --resume
```

跑完后由统一 runner 把候选 `py/` 拷进 scratch，执行 `main.py`、`solve`，再验算。定位分看最后一个 `reason_code` 是否等于隐藏真值。修复分看目标项是否通过，且没有新增 NG。

## 并行还是串行

`--jobs` 只作用于 T1–T5，默认 1。这些架构的生成可以并行。正式验算都要打到本机 OSIS（端口 18080），求解阶段不要和建模线的求解重叠。

T6 独占隔离 OpenCode 和 OSIS，campaign 始终把它放在串行队列，`--jobs` 对它无效。不要同时开两个 T6。

`--resume` 跳过已经完成的 run。结果在 `runs/<label>/`，不进 Git。汇总方法见 [实验数据后处理.md](实验数据后处理.md)。

## T1–T5

驱动按架构选择解释器：T1、T2 用仓库 `.venv`，T3–T5 用 `.venvs/t3`、`t4`、`t5`。

| 架构 | 动作 | 技能怎么给 | 候选工程怎么改 |
| --- | --- | --- | --- |
| T1 | 一次请求，禁止第二次补问 | 技能正文和当前候选文本放进提示词 | 回复中的 `### FILE:` 块，路径必须落在候选工程内 |
| T2 | LangGraph `create_agent`，流式 ReAct | JSON 工具：技能列表、正文、参考文件、案例搜索 | 列举、读取、写入候选文件。没有单独的语法检查工具 |
| T3 | smolagents `CodeAgent` | `tools=[]`。用 `pathlib` 读快照。放行 `json`、`pathlib` | 用 `pathlib` 改候选文件 |
| T4 | OpenHands 默认智能体 | `load_skills_from_dir`，先 `invoke_skill` | 官方终端和文件编辑器，工作目录是候选工程。浏览器关闭 |
| T5 | CrewAI 三角色：诊断、修复、复核 | `Crew(skills=...)`。`load_skill` 只给 `SKILL.md`，参考文件走 `read_skill_resource` | 诊断和复核只用读工具；修复者用 `FileWriterTool`，目录限制在候选工程。允许委派 |

T1–T5 在进入 OSIS 之前有语法编译门禁。编译失败的候选不会当成修复成功。

## T6

T6 使用父仓库的 OSIS-AI 指令，但只挂本 run 的无模板快照和当前候选工程，不连接父仓库已经打开的、带原始模板库的 OpenCode。评测阶段没有语法硬门禁：`main.py` 跑不起来会在重建时失败。这与父仓库 `--rebuild` 一致。
