# 六框架使用说明

## 共享合同

T6 直接使用父仓库验算修复代理及其 OpenCode 里的技能和工程。T1–T5 拿到同一份技能树的完整副本，以及同一份 staged 候选工程。差别只在框架。Runner 把外部 seeded 工程复制到 ignored run 的 private 区和 candidate_project。Adapter 只收到净化任务、candidate 根、这份技能树、模型与预算。候选工具拒绝绝对路径、父目录跳转和非文本文件。

## T1 Direct

T1 没有工具循环。Harness 在一次请求中加入公开任务、确定性的技能正文包与当前候选文本。回复中的 FILE 块经过同一 CandidateWorkspace 路径门禁后写入。任何第二次补问都会改变架构定义，因此禁止。

## T2 LangGraph

T2 使用 langchain.agents.create_agent 和 stream_mode=values。LangGraph 没有领域工具，调用方传入与建模线相同的读取面：技能索引、技能正文、参考文件、模板文件列表、案例搜索，以及候选工程的列举、读取和写入。不另加语法检查工具。

## T3 smolagents

T3 使用 CodeAgent，`tools=[]`。解释器放行 `json` 和 `pathlib`，模型自己读技能快照并改候选文件。不注册自建读写工具。

## T4 OpenHands

T4 通过 `load_skills_from_dir` 挂载技能，工具用 `get_default_tools(enable_browser=False)`：终端、文件编辑器和任务跟踪。提示词要求先调用 InvokeSkillTool，再用框架自己的终端和文件编辑器。不注册自建读写工具。

## T5 CrewAI

T5 为 diagnoser、repairer、verifier 顺序流程。`Crew(skills=...)` 挂载技能，`allow_delegation=True`。读写用 CrewAI 的 DirectoryReadTool、FileReadTool、FileWriterTool，范围限制在候选目录。诊断者和复核者只有读工具，修复者可以写。`load_skill` 只返回 SKILL.md，因此保留一个 `read_skill_resource` 读取 references、scripts、assets。代码解释器保持关闭，与建模线一致，因为该工具已废弃。

## T6 OSIS-AI

T6 不在本仓库启动 OpenCode，也不改权限。它调用父仓库 `datasets/check_repair/run_eval.py` 的 `chat_via_agent`，连父仓库已经在跑的 OpenCode，把父仓库写回的 `py/` 同步到候选工程。

评测对齐父仓库 `--via agent --osis --rebuild`：拷贝 `py/` 到 scratch OSIS 工程、执行 `prep/main.py`、`solve`，再 CheckSolve / CombinationAndCheck。T6 **没有**语法编译硬门禁；`main.py` 跑不起来会在重建阶段失败，这与父仓库 `--rebuild` 一致。T1–T5 仍保留语法编译门禁。Campaign 无论 jobs 设置为何值都串行执行 T6。
